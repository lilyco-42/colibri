## On-board oracle inference

Fixture: deterministic random tiny Qwen3.6-shaped hybrid (DeltaNet, attention and routed experts), generated by upstream `c/tools/make_qwen36_tiny.py --ref-mode full`, converted using `c/tools/convert_qwen36.py --ebits 8`. The fixture is **not human-language-capable** and is under 1 MiB of weights.

From the staged experiment:

```sh
BASE=/dev/shm/lyco-colibri-a7a
cd "$BASE/runtime"
COLI_NO_OMP_TUNE=1 COLI_DENSE_I8=0 OMP_NUM_THREADS=4 \
  SNAP="$BASE/fixture/qwen36_tiny_c" \
  ./qwen36 1 8 "$BASE/fixture/qwen36_tiny/ref_full.json"
```

Observed result: `Matching tokens: 16/16`; exit code 0; max resident set size ~8.7 MiB. Repeated run matrix:

| Expert cache slots per layer | Runs | Token oracle | Exit |
| --- | --- | --- | --- |
| 1 | 2 | 16/16 each | 0 |
| 2 | 1 | 16/16 | 0 |
| 8 | 2 | 16/16 each | 0 |

The reported 760–950 synthetic tokens/s and very small RAM usage reflect toy dimensions **only**. Do not use these values to predict performance of an 8–744B checkpoint or ordinary chats.

## Multiturn prefix-cache contract

Downloaded the upstream tests `c/tests/prefix_serve_harness.py` and `c/tests/test_qwen36_prefix_serve.py` to RAM and executed:

```sh
cd /dev/shm/lyco-colibri-a7a/runtime
QWEN36_TINY=/dev/shm/lyco-colibri-a7a/fixture/qwen36_tiny_c \
  COLI_NO_OMP_TUNE=1 OMP_NUM_THREADS=4 \
  python3 -m unittest -v tests.test_qwen36_prefix_serve
```

Result: **6 tests passed**, including divergent prompt, shorter-after-longer, reply replay, prefix reuse on/off comparison, normal reuse, and three-turn repeated reuse. The test harness emitted Python `ResourceWarning` about file objects; tests all passed.

## Safety and current limits

- Original `a7a-llama.service`, `a7a-lyco-meter-bridge.service` and `a7a-lyco-meter-tunnel.service`: **active** at final verification.
- Original model health: `{"status":"ok"}`. VPS gateway `lyco-ai-gateway`: **active**; upstream health `{"ok":true,"upstream":"available"}`.
- Root filesystem `/dev/mmcblk1p3` ext4 `errors_count`: **5** before / throughout / after testing; no new ext4 error observed.
- All experimental binaries, fixture weights, test files and logs are under `/dev/shm/lyco-colibri-a7a` (tmpfs), about 8.7 MiB RAM; lost on reboot by design.
- The full Qwen3.6-35B MoE checkpoint needs far more memory and model storage than this 3.8 GiB RAM board offers; Colibri cannot load the GGUF files currently used by llama.cpp.
- Do not enable experimental Colibri as the public LYCO AI backend until hardware is upgraded and a compatible human-language checkpoint is provisioned on reliable storage.

No production model switches, root filesystem writes, package installations, or system reboot were performed by this test series.
